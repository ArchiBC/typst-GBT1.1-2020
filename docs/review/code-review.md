## 构建和过期结果处理

`tools/build.py` 统一构建两套字体，每套先生成对应的 32 个真实示例再编译主书。示例缓存的输入哈希覆盖实际字体文件、模板、示例源码及构建脚本；不使用另一套字体的旧片段。`output/build.json` 记录源文件、构建输入、主书和示例哈希；参考版本的两个 PDF 别名同步校验。

`compile.py` 支持一般源文件和 `--input KEY=VALUE`，普通标准不需要原 PDF 或 OCR 数据。`render_outputs.py` 记录 PDF 哈希，删除同一预览目录里已经不存在的旧页图，不影响其他人工对照图。`page_audit.py` 只在 PDF 哈希相同的情况下复用人工确认的内容页码映射；OCR 相似度不自动宣告通过。

新增两个可重复执行的交付检查：

- `tools/verify_delivery.py`：验证人工记录对应当前主书及两套 PDF、构建输入没有过期、别名一致、编号和表 F.1 检查已完成。
- `tools/verify_bundle.py`：在新目录解包，以开源字体重新生成全部真实示例、主书、示例标准和手册并执行自动检查；关闭本机参考字库路径，比较重编书与交付开源版每页正文。
